Adds vanilla 7 Days to Die support with an AMD64 runtime image, bilingual server setup and configuration, join information, logs and game-update entry points. Existing game servers do not need to restart for this panel update.

## Features

- Add vanilla 7 Days to Die V3.3.0 support, including SandboxCode gameplay settings and TCP/UDP port reservations. ([#162](https://github.com/smartcat999/game-panel-lite/pull/162))
- Keep existing world identity read-only. Require stopped servers for save-only backups and replace the save directory on restore.
- Share Provider-declared Steam update metadata with Palworld while preserving its existing behavior.

## Validation and limitations

- The complete AMD64 image was built on um773 with Steam Build ID `25661908` (V3.3.0 b18). An isolated instance started, saved and exited normally; a replacement container loaded the same save directory without downloading game files again.
- Real startup identified and fixed the unsupported `SaveGameFolder` property.
- The test environment showed intermittent EOS connection failures and a Steam game-server login timeout. Steam/EOS access must be reliable; a failed startup may require retrying after connectivity is restored.
- Actual player joining, player progress across restart and a live game-file update have not been verified. Mods, console commands and scheduled live backups are not supported for this Provider yet.

## Upgrade notes

No existing game-data migration is required. Updating briefly recreates the API, Web, exporter and updater services. Existing game containers and saves are preserved. Seven Days to Die is Linux AMD64 only; publish the base port over TCP and UDP, plus base+1 and base+2 over UDP.
