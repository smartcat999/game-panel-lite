# 支付通知入口

## 边界

`POST /api/commerce/payments/webhook` 只负责接收支付渠道的原始通知。HTTP 不把请求 JSON 直接转换成 `CapturedPayment`，也不根据客户端提供的金额、币种或时间授予权益。

`paymentingress.Service` 定义两个消费侧端口：

- `Verifier` 由具体支付渠道 Adapter 实现，负责验签并校验商户、环境、事件身份、最终支付状态、订单、金额、币种和渠道支付时间。
- `Recorder` 记录已经验证的 `CapturedPayment`，继续使用数据库中的事件与交易唯一约束处理重复和冲突。

渠道 Adapter 未配置时入口返回 503，不能回退到无验签 JSON。验证失败不调用 Recorder。验证成功后只原子记录到账并写持久履约任务；订阅和权益由已有 Fulfillment Worker 异步处理，HTTP 不直接发放服务，也不忽略履约失败。

## 上线条件

当前仓库没有选择真实支付渠道，因此生产组合根没有注入 `Verifier`。接入具体渠道时必须补充：

- 官方 SDK 或协议版本、商户和环境绑定；
- 签名证书／密钥的外部 Secret 配置和轮换；
- 原始请求大小限制、渠道要求的必要 Header 及时间窗；
- 渠道沙箱的真实重复、乱序、金额不符、退款和对账证据；
- 回调公网域名、账户授权和上线审批。

单元测试中的 Verifier 是端口测试替身，只证明未验证请求不能到达账务记录，不作为真实支付验收。
