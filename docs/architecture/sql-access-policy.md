# SQL 访问边界

2026-09-08 用户要求：所有 SQL 操作禁止连表 JOIN，使用 ID 查询或批量查询，在代码中组合数据。本要求适用于本次六阶段改造，包含业务查询和迁移执行路径。

- 不新增显式 JOIN、隐式多表连接，也不以跨表关联子查询替代 JOIN。先查归属／关系 ID，再批量读取目标记录。
- 禁止逐条查库的 N+1 模式；ID 查找有界分批，结果按稳定 ID 映射，明确处理缺失记录和归属不一致。需要保留整组资源排序／截断的旧列表可将已查询的 ID 集合作为单个 JSON 参数传入，不能重新关联其他业务表。
- 需要一致性的多次读取使用数据库快照。事务准入与权限变更继续保持原有写锁和提交前复核，不把早先读取的权限当作永久授权。
- 分页、排序、总数和筛选语义必须保持；不能仅对已截断的一批数据排序或分页。跨区域数据通过服务契约读取，不跨库连接。
- 无 JOIN 本身不证明性能达标。通过查询次数、执行计划、索引、负载和延迟测量验证结果；不要一次拉取无界全表来拼接。

当前已替换三个在线 JOIN：全局修订资源读取、实例成员权限、用户组织列表。全局修订和组织读取按 500 个 ID 分批，该值只控制数据库参数规模，不是租户限额。

世界、预设、模组库和活动记录已改为使用物化的组织 ID；超过 500 个 ID 时在数据库内展开单个 ID 集合参数，避免超过参数数量限制，同时保留资源查询整体排序／LIMIT。这不是对其他业务表的子查询。需继续测量大集合的解析成本和执行计划，不能将功能测试当作性能证明。

实例列表／分页／详情、备份归属和当前实例活动记录也已改为独立 ID 查询，在同一只读快照内组合；分页计数与取页使用同一权限 ID 集合。NULL 组织字段保持为 NULL，不将其转换成空字符串归属。

节点制品授权已独立查询组织 ID，并保留执行前的租约和版本复核；任务删除在事务内锁定、读取并分批删除同一组 ID，制品引用删除失败时整体回滚。SQLite 制品引用回填按任务 ID 分页、批量读取制品归属并在代码中组合，非法清单中止迁移且不记录成功版本。

SQLite 端口回填已改为分批读取实例和任务清单，在代码中解析并批量写入全部历史占用者；非法端口和 NULL 占用者中止迁移。PostgreSQL 006／014 使用对应 Go 回填，历史 SQL 字节继续作为校验和身份；仅匹配完整历史版本、名称、内容才采用替代执行。

世界和活动归属回填已改为分页读取目标 ID、批量查实例归属、使用单表 CASE 批量更新；仅补全缺失归属，不覆盖已有归属，也不认领孤儿记录。SQLite 启动回填在同一事务内执行，PostgreSQL 002／003 同样使用兼容执行，旧 SQL 文件保持不变。

区域过滤先读取明确匹配的节点 ID，再筛选实例；空区域不再默认为香港，分页和计数使用同一只读快照。旧列表的大 ID 集合仍需测量内存、JSON 解析及执行计划。

当前生产 Store Go 源码扫描未发现显式 JOIN／跨表过滤子查询；历史 002／003／006／014 通过已匹配的替代实现执行。后续仍需补充生成 SQL 防回归检查和负载证据，不能用静态扫描或例外清单冒充全部容量达标。历史脚本须由应用迁移器执行，不能绕过它直接运行已被替代的旧 SQL。
