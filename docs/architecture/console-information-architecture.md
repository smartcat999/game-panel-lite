# 控制台信息架构

## 目的

GamePanel Lite 提供租户控制台和平台控制台。两者服务不同任务，不是同一个资源选择器中的两种范围。

## 账号与入口

- 账号身份决定用户是否能进入平台控制台。
- 租户成员关系决定账号能进入哪些租户空间，以及在空间内的角色。
- 租户切换器只列出当前账号具有成员关系的空间。
- 平台管理员从账号菜单进入平台控制台；平台角色本身不等于任意租户的成员关系。
- 代管租户必须从平台租户详情显式发起，并记录操作者、目标租户、时间和原因。未实现代管审计前不提供隐式进入任意租户的入口。
- 语言和主题属于账号偏好，在两套控制台中保持一致。

## 租户控制台

租户控制台围绕用户购买和管理的逻辑资源组织：

- 实例：创建、配置、启动、停止、重启和删除。
- 世界与存档：导入、备份和恢复。
- 模组：租户资产和实例安装。
- 空间管理：成员、账单、用量和租户配置。

创建实例时用户选择规格和区域。区域自动选择节点；只有获得专属节点权限的用户才可严格指定节点。普通租户页面不展示节点清单、调度队列、执行租约或宿主机指标。

## 平台控制台

平台控制台包含两个职责分组。

业务控制面管理：

- 租户、账号和成员关系。
- 套餐、订单、账本和权益。
- 全局逻辑实例、不可变配置版本和部署归属。
- 审计、风险和客服处置记录。

基础设施运维管理：

- 区域目录、创建准入和健康摘要。
- 区域内节点、容量、调度、执行任务和部署实际状态。
- 区域日志、指标、告警和故障处置。
- 区域存储和备份执行状态。

区域选择器只在基础设施运维页面出现。它是运维查询范围，不改变租户资源所有权，也不成为租户控制台的全局上下文。

## 资源关联

```text
租户
  └─ 全局逻辑实例
       └─ 部署归属（区域、归属版本）
            └─ 区域部署
                 └─ 资源预留与节点
                      └─ 有限期执行授权与运行观测
```

租户实例详情显示区域、部署状态和面向用户的故障信息。平台区域页面显示区域部署、节点、容量和任务，并可通过全局实例 ID 进入平台实例详情。

平台实例详情用于追踪身份、租户归属、配置版本和区域执行链路，不提供租户侧配置或生命周期操作。需要处理业务配置时回到租户控制台；需要处理执行故障时进入所属区域的运维页面。

全局和区域通过 `organization_id`、`server_id`、`placement_epoch`、`revision_id`、`spec_generation` 和 `intent_version` 关联。查询分别读取单表数据，再按 ID 批量查询并在代码中组合，不使用 SQL JOIN。

## 当前路由

| 路由 | 职责 |
| --- | --- |
| `/servers` | 当前租户的实例管理 |
| `/servers/[id]` | 当前租户的实例配置与生命周期 |
| `/settings` | 当前租户空间设置 |
| `/account/settings` | 当前账号语言与主题 |
| `/platform` | 平台概览 |
| `/platform/organizations` | 平台租户管理 |
| `/platform/instances` | 平台逻辑实例追踪 |
| `/platform/instances/[id]` | 全局实例与区域部署关系 |
| `/platform/regions` | 区域目录 |
| `/platform/regions/[id]` | 区域部署、节点、容量与任务 |

## 后续边界

- 平台租户详情需要独立路由，承担订单、权益、用量和审计查询。
- 代管租户需要显式会话、期限、原因和审计，不复用普通空间切换状态。
- 平台实例详情需要接入正式的逻辑实例和 Placement 读取模型，逐步停止依赖旧兼容服务器资源响应。
- 区域部署的处置操作必须调用所属区域的受信运维接口，不能直接写全局数据库或租户配置。
