# 租户资源配额

创建空间实例和更新配置通过 Store 的分配接口执行。事务先锁定空间行，再核对并锁定写入成员关系，读取持久化配额、统计已有实例预留，并提交资源配置。平台管理员可以绕过成员关系，但仍受空间配额约束。空空间的自托管实例保留原有行为。

预留口径为所有已保存实例的期望 CPU 和内存上限；停止和等待删除的实例继续占额，记录删除后释放。`usedCpuCores`、`usedMemoryMb` 表示配置预留，不是运行时实测消耗。实际节点调度仍须独立检查容量，尤其缩容尚未由运行节点应用时，不能据此认定物理资源已经释放。

配置更新以原始 spec、节点和空间为条件，拒绝旧快照，只写入 spec 和更新时间，不覆盖运行状态。旧内部 SaveGameServer 在空间实例资源变化时也会检查配额。CreateGameServer 仍是内部初始化原语；外部空间创建必须使用 CreateAllocatedGameServer。后续应完成所有写入用例收口与归属迁移协议，不能把这些接口当作完整 RLS 或分布式调度实现。

配额修改不再给缺省/非正字段填入隐式额度：负数和非有限数无效，零表示零额度。降低配额不能低于已预留量。缺少配额记录会拒绝分配。CPU 和内存必须为正数，旧的不限量空间实例会阻止新分配；包含多个不限量实例的历史空间仍需整体迁移为有限配置，本批不自动替用户选择额度。

验证包含 SQLite 与真实 PostgreSQL 的八请求竞争两个额度、超额创建/扩容、额度下调、停服占额、删除释放、旧配置拒绝、撤权和缺失配额。HTTP 验证创建超额返回 409、不限量返回 400。未验证生产规模吞吐；当前统计按空间读取实例，不应将此作为超大单租户性能结论。

存储 GB、文件上传和备份空间尚未执行物理配额；节点容量预留、运行实例缩容确认、可靠删除、分布式租约、计费权益及历史资源迁移仍未完成。

空间列表 GET 现在只读取数据，空列表返回 `[]`。不再在读取时创建硬编码的默认空间、赋予首个账号 owner 身份，或把未归属实例批量挂入空间。现有空间不受影响；注册创建个人空间、管理员显式创建空间仍由各自写入用例负责。历史实例接管需要独立的归属、配额及文件迁移事务，尚未提供自动迁移工具。

玩家日志同步通过 PlayerStore 的人数观察接口写入，仅允许修改观察快照中的人数。保存时对比原运行状态、节点和空间；若日志读取期间已经停服、换容器、迁移或删除，丢弃旧结果。配置改动不会被人数同步覆盖。该检查不提供多进程观察顺序或 Controller 的完整状态字段所有权；这些仍需在租约与观察版本协议中收口。

生命周期命令通过 SaveServerLifecycle 提交，写入范围限定为期望状态、配置 generation、模组同步模式、过渡阶段与时间。资源配置、玩家人数等字段不接受命令调用方覆盖。事务复核空间成员写权限，SQL 同时比较原 spec、运行状态、节点和空间；竞争变更返回 409，存储不可用返回 500，不能统一伪装成 404。删除的停止状态校验与保存共用一个快照；已提交删除意图后，启动、停止、重启及重复删除返回 409。

以上只约束生命周期请求的数据库提交，尚不代表实际容器删除与文件清理具有分布式排他性。Controller 删除副作用、任务 outbox、租约及观察版本仍需完成。测试覆盖同一快照的八个并发命令最多一个成功、配置/状态/归属改变后的拒绝、撤权与已删除记录不会重新插入。
