# 全局拥有逻辑资源，区域拥有部署与执行

2026-09-08：用户确认全局管理、区域自治、节点执行；资源部署层级仅为 Region → Node，全局控制面不是资源树中的父资源。游戏服务器的逻辑身份、配置版本、期望状态、权益及部署归属由全局拥有；Region 独立拥有部署、节点、预留、执行任务、观察状态和监控，各 Node 仅执行所属区域授权的任务。这样跨区域迁移不改变用户资源身份，并允许区域在全局短暂不可用时维护既有运行。

跨层使用业务事务内 Outbox、消息队列、接收端 Inbox 与持久任务实现可重试交付，不将现有 game_servers 整表搬入区域库，也不允许区域另行修改用户配置。代价是跨库操作必须有幂等、补偿、对账和明确的断连授权期限；版本检查不能替代旧实例的物理隔离。

普通用户只选择 Region 和规格，区域自动选节点；专属用户与运维可在授权范围内严格指定节点。首期迁移采用停服迁移，普通停服释放已确认不用的计算容量，保留资产；稳定逻辑域名不代表固定 IP、端口或连接不断开。完整契约见 [目标蓝图](../architecture/architecture-target-blueprint.md)。本决策描述目标，不代表当前代码已完成。

用户随后确认当前 Region + Node 已满足部署层级需要，撤回提前引入 Cell 和 cellId 的建议。本期区域直接调度节点；节点池可用于分类与授权，不增加新的自治控制面或数据库层级。
