# 控制台切换管理范围，不切换用户角色

2026-09-09：控制台顶部入口用于选择当前管理范围，不允许用户主动切换或伪装角色。平台管理员、租户空间管理员和普通用户不是三个并列视角：平台管理员是账号的全局权限；租户空间管理员和普通用户是账号在某个空间内的成员角色。同一账号可在不同空间拥有不同角色。

## 权限模型

- 账号只保存平台角色：`platform_admin` 或 `user`。
- 空间成员关系独立保存：`owner`、`admin`、`member`、`viewer`。
- 当前控制台范围只有两种：平台范围，或一个确定的租户空间。
- 平台管理员可以进入平台范围，也可以进入任意租户空间进行支持与排障。普通账号只能进入自己仍然有效的空间。
- 切换范围不修改账号角色或成员角色。前端展示的角色标签不是授权依据。

现有账号级 `admin/member/viewer` 与空间成员角色重名，容易把平台权限泄漏到租户操作；现有 `PerspectiveProvider` 的 `super/admin/user` 只保存在浏览器中，也没有后端授权含义。实现时应由新的控制台范围上下文替代，不继续扩展这套本地视角。

## 顶部入口

顶部左侧保留一个上下文切换按钮，内容固定为：范围图标、当前范围名称、当前角色说明、展开箭头。不要增加数字徽标，也不要把账号头像菜单合并进来。

平台管理员处于平台范围时显示：

```text
[平台图标] 平台管理  ·  平台管理员  [展开]
```

进入租户空间后显示：

```text
[空间图标] 极客公会  ·  空间管理员  [展开]
```

普通用户显示：

```text
[空间图标] 极客公会  ·  成员  [展开]
```

账号头像菜单只负责账号设置、安全设置和退出登录。Region 属于资源部署与筛选条件，也不放入这个入口。

## 展开菜单

平台管理员的菜单分为两个区域：

1. `平台管理`：唯一的平台范围入口。
2. `租户空间`：可搜索的空间列表，每项显示空间名称，以及该账号在空间内的角色；平台管理员代管没有成员身份的空间时显示“平台代管”。

非平台管理员只显示有成员关系的空间。空间较少时直接列出；空间较多时出现搜索，不在菜单中分页显示复杂表格。最近使用的空间可排在前面，但不改变权限结果。

当前项使用勾选状态。点击当前项只关闭菜单；点击其他项立即开始切换，不再弹确认框。

## 切换流程

1. 前端先请求目标范围的可访问性，后端按账号和空间 ID 重新校验平台角色或成员关系。
2. 校验成功后更新当前范围，停止旧范围的日志流、状态流和轮询请求。
3. TanStack Query 的业务缓存键必须包含范围类型和空间 ID；切换时取消旧请求并使目标范围数据失效。
4. 跳转到目标范围可用的默认页面。平台范围进入平台概览；租户范围进入实例列表。若当前路由在新范围仍合法，可以保留同类页面，但不能保留旧空间的资源 ID。
5. 最近使用的范围保存为账号偏好；浏览器本地值只能用于首屏加速。深链接中明确的空间优先于最近使用值。

当空间被删除、成员被移除或角色降级时，后端返回不可访问。前端立即清除该范围的业务缓存并切换到第一个可访问空间；没有可访问空间时进入“暂无可用空间”页面。平台管理员若正在代管租户，页面顶部持续显示“正在代管：空间名称”，并提供返回平台管理的入口。

## 导航差异

平台范围导航只包含全局能力，例如租户、订单、套餐、Region、节点、平台监控与审计。

租户范围导航只包含该空间的实例、存档、备份、模组、成员、账单与空间设置。`owner/admin` 可见成员和空间设置；`member` 可创建和操作授权资源；`viewer` 只读。隐藏菜单用于减少干扰，所有接口仍在后端逐次校验。

## Region 与 Node 管理

平台管理员进入平台范围后，侧边导航增加“基础设施”，其下包含“区域”和“节点”。Region 是基础设施资源层级，不是登录身份，也不是租户空间，因此不放进顶部的账号／空间上下文切换菜单。

### 职责关系

租户空间与 Region 不是两套对等的资源管理视角。租户空间管理组织拥有的业务资源及其期望状态；Region 运维管理区域执行能力与实际状态。全局逻辑实例是租户资源，区域 Deployment 是执行记录，不能把 Deployment 当作另一份可独立编辑的租户实例。

- 租户空间负责实例配置、规格、目标 Region、生命周期请求、备份策略和成员权限，表达“希望系统做什么”。
- Region 负责节点、容量、端口、调度、持久任务、运行状态、监控和故障处置，回答“区域实际做到了什么”。
- 平台全局管理负责租户、订单、权益、逻辑实例、Placement 和 Region 目录，并在两侧之间分发期望状态、汇总实际状态。
- Region 运维只能执行重试、重新调度、隔离、排空和恢复等基础设施动作；不能在 Region 页面改写租户配置、订单、权益或用户期望状态。

两侧通过稳定的全局实例 ID、Placement epoch、配置 generation 和意图版本关联。Region 页面只读取完成运维所需的租户标识和逻辑实例摘要；需要查看业务资源时，跳转到平台范围内的全局实例详情，不切换或伪装成租户身份。

### 区域总览

`平台管理 / 基础设施 / 区域` 展示所有 Region。首屏使用紧凑表格，每行显示区域名称、区域状态、调度状态、资源容量摘要、监控更新时间和操作入口；不使用带小数字的菜单或装饰性统计徽标。

点击某个 Region 进入 `/platform/regions/{regionId}`。Region 详情页固定显示区域名称和状态，内容分为：概览、节点、工作负载、任务、监控、配置。这里的标签页切换 Region 内的运维功能，不改变平台管理员身份。

“工作负载”展示区域 Deployment，而不是可编辑的全局实例副本。列表可显示实例名称、所属租户、Node、期望／已观察版本、运行状态和最近错误；详情中的业务配置只读。平台管理员要修改业务资源时，应进入平台全局实例详情并遵循对应权限和操作流程。

### Region 间切换

在 Region 详情页的页头使用一个独立的 Region 选择器：

```text
区域：华东一区 [展开]
```

选择其他 Region 后只替换路由中的 `regionId`，例如从 `/platform/regions/cn-east-1/nodes` 切换到 `/platform/regions/cn-north-1/nodes`。如果目标 Region 支持同类子页面，保留当前标签；否则进入目标 Region 概览。刷新和分享链接都应保持同一个 Region，不能只存在浏览器内存中。

Region 选择器只在基础设施相关页面出现。租户用户在创建实例时选择部署 Region，或按 Region 筛选自己的实例；这里的 Region 是部署属性和筛选条件，不是进入基础设施运维页面的入口，租户用户也不能看到 Node 清单。

### Node 管理

`/platform/regions/{regionId}/nodes` 只查询该 Region 的节点。Node 表格显示节点名称、运行状态、可调度状态、运行时能力、已分配资源、最近心跳和操作。点击节点进入节点详情，查看基本信息、容量、工作负载、监控和操作记录。

平台管理员可以执行以下明确操作：

- 加入节点：生成短期、一次性加入凭据，由节点主动注册到指定 Region。
- 禁止调度／恢复调度：只影响新实例调度，不停止已有工作负载。
- 排空节点：先生成影响清单，再提交异步排空任务；不把跨 Region 迁移作为默认能力。
- 移除节点：仅允许已禁止调度、无活动工作负载且符合离线策略的节点。
- 修改节点标签和租户授权范围：用于专属节点、运行时能力和调度约束。

Node 不允许通过前端从一个 Region 直接改到另一个 Region。需要调整归属时，应先在原 Region 安全移除，再以新身份加入目标 Region，避免两个 Region 同时控制一个节点。

### 控制面与 Region 的交互

平台页面读取全局控制面中的 Region 目录和汇总状态。Region 的节点、监控和实际执行状态由各 Region 自己维护，再异步上报控制面形成只读摘要。

平台管理员提交禁止调度、排空、配置更新等操作时，全局控制面先写操作记录和 Outbox，再通过消息队列投递到目标 Region；Region 使用 Inbox 去重、创建本地任务并执行，随后异步上报状态。页面展示“已提交、执行中、成功、失败”状态，并通过控制面的短轮询或事件流更新，不让浏览器长期直接连接每个 Region。

切换 Region 只改变当前查看和操作目标，不迁移资源、不修改节点归属，也不取消已经提交的异步任务。任务中心始终可以按操作 ID 查询最终结果。

所有平台基础设施接口使用明确的 Region ID，例如 `/api/platform/regions/{regionId}/nodes`。控制面先查 Region，再按 ID 批量查询节点摘要并在代码中组合，不使用 SQL JOIN。Region 内部接口只能由控制面服务身份访问，浏览器不直接持有 Region 凭据。

## 接口边界

- 平台接口使用明确的 `/api/platform/...` 路径并要求 `platform_admin`。
- 租户接口必须带确定的 `organizationId`，由路径或请求体传入；不使用前端传入的角色，也不接受“当前管理员”之类的隐式绕过。
- 登录引导返回平台角色；空间列表返回每个空间对应的成员角色。两类角色分别计算权限。
- 数据库继续按账号 ID、空间 ID 分步查询和批量查询，在代码中组合数据，不使用 JOIN。

## 首期实现顺序

1. 拆开平台角色与空间成员角色，补充带成员角色的空间摘要接口。
2. 用 `ConsoleContextProvider` 替换本地 `PerspectiveProvider`，使查询键和路由携带范围。
3. 实现顶部上下文切换菜单和平台代管提示条。
4. 将侧边导航与页面权限改为由当前范围和后端权限共同派生。
5. 验证跨空间切换、撤权、降级、刷新恢复、深链接及旧请求不会污染新范围。

本决策先固定交互和权限边界。当前硬编码的 `GamePanel Cloud 管理员` 顶部入口不应直接扩展成可点击的角色切换器。
