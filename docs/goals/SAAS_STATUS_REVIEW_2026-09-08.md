## 当前应优先处理的问题

1. **失联重调度缺少旧实例隔离证据。** `apps/api/internal/server/controller.go` 默认开启 autoEviction，失联超时后删除任务并选择新节点；该分支未先确认旧容器终止、隔离旧写入或完成存档转移。租约到期不等于旧游戏进程停止，存在双实例运行和存档分叉风险。先完成隔离/恢复状态机或限制自动恢复行为，再验收跨节点故障恢复。
2. **积分并发与开服事务不完整。** `apps/api/internal/store/credits.go` 先读取余额，再写计算好的绝对余额；扣减语句未检查 RowsAffected。并发操作可能丢失扣款/充值，条件更新未生效时仍记录流水。`apps/api/internal/http/server_handlers.go` 先独立扣积分、再创建实例，创建失败缺少同事务回滚或可靠补偿。这些是代码审阅发现，尚未用新增并发用例复现，不能进入真实收费。
3. **OAuth PostgreSQL 表名不一致。** 当前 GORM 实测 `NamingStrategy.TableName("OAuthIdentity")` 为 `o_auth_identities`；010 SQL 创建的是 `oauth_identities`，模型没有 TableName 覆盖。当前 PG 集成通过不代表 OAuth 可用，因为该路径未被覆盖。
4. **节点调度字段迁移已补齐，但尚未提交。** 011 增加 `unschedulable boolean NOT NULL DEFAULT false`；验证了旧节点字段保留、新节点默认值、非空约束和重复迁移保留禁止调度状态。原先导致 PG 集成失败的这一缺口已在当前工作区修复。
5. **代码边界与硬编码仍需收口。** 调度器中的游戏架构规则应来自 Provider 能力；开服费用应来自明确的套餐/计费规则。多个 HTTP Handler 仍承担业务编排，不能把文件拆开或新增接口等同于模块化完成。
